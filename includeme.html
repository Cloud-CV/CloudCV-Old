DIGITS Documentation¶

Homepage¶

It calls the method get_job_list() (digits/views.py@74) that fetches all the datasets and models for all jobs and returns them in json format (if requested via the API) or as HTML (if accessed from the webapp). The new_dataset_options, running_datasets, completed_datasets, new_model_options and running_models variables hold the data in the webapp display mode.

Jobs¶

DIGITS handles datasets and classification models in exactly the same fashion, jobs. The show_job (digits/views.py@86) , edit_job (digits/views.py@103) , job_status (digits/views.py@119) and delete_job (digits/views.py@138) functions handle the respective CRUD options for both, models and datasets, quite elegantly. These functions are called from the UI through the JS snippets present in (digits/templates/job.html@82-170).

Job Details¶

On home page, when we click on any of the Datasets/Models shown there, it creates a GET request to /job/<job-id>, which then (depending on the type of job) redirects to :

  • the /datasets/<job-id> to show the details about the specific DatasetJob (digits/dataset/views.py@15). The details include Job Information, Parse Folder, Create DB (train) and visualizations for the Create DB(train) and Create DB(val).
  • the /models/<job-id> to show the details about the specific ModelJob (digits/model/views.py@27). The details include Solver, Network(train/val), Network(deploy), Raw Caffe Output, details about the dataset used along with the visualization of the Accuracy and Loss that occurred.

Job Status¶

To get the status of a job in the json format, you can simply goto /jobs/<job-id>/status. The ‘jobs’ in this URL can be replaced, quite obvious now, with ‘models’ or ‘datasets’. The job_status() (digits/views.py@118) method handles this task.

Job Update¶

If you want to change the name of a Model/Dataset, then go to home page and then click on the Model/Dataset that you want to rename and you will see a new page. Goto the top where the name is written and you will see the edit button just after the name of Model/Dataset. Then edit the name and click Update. The updateJobName() (digits/templates/job.html@92) JS function calls the edit_job (digits/views.py@103) function to execute this task.

Creating a Job¶

Creating Dataset¶

On home page of DIGITS, first click on the Images button and then you will see a bunch of options available. Click on one of the categories that you are looking for. For eg. we are going to add the dataset in Classification Model. So, clicking on Classification will give redirect to the url /datasets/images/classification/new and we will see a bunch of options for our Dataset type. Select the appropriate values and and a Dataset Name, then click on the Create button and then you can see a screen similar to the below image.

The image_classification_dataset_new() method present at (digits/dataset/images/classification/views.py@217) handles this task via a POST request, or you can use the webapp via a ‘GET’ request to obtain a form for the new dataset using image_classification_dataset_create() method located in the file (digits/dataset/images/classification/views.py@207).

Creating Model¶

For creating a new Model, a Dataset is required. On the right side of home page, under New Models, there is a button Images. Choose Classification from the dropdown list that is shown by clicking on Images Button. After this, you will be redirected to the url /models/images/classification/new. Now, select one of the Dataset, choose one of the Networks and you can change the parameters in the Solver Options. Also, you can create a custom network yourself using a .prototxt file.

You can use the image_classification_model_create() method from the file digits/model/images/classification/views.py@49 to achieve this task.

Delete Job¶

A previously created job (dataset/model) can deleted (or even aborted in the case of a model) using DIGITS. Simply click on the delete button associated with the DatasetJob or ModelJob.

Classify a Model¶

To classify a Model, goto the homepage of DIGITS and click on one of the Model under the completed category. It will take you to the link /models/<job-id> (digits/model/views.py@27) where at the bottom of the HTML page, there are lot of options for classifying.

For classifying a Model, DIGITS provides the functionality to classify using Single Image, multiple images, using a .txt file (digits/templates/models/images/classification/show.html@160) or through a URL of an image or set of Images. Select the way in which you want to classify and click the classify button and here you go. You will see a list of classification results according to the images supplied and their percentage predictions. The respective methods for these options of classification can be found as follows :

  • image_classification_model_classify_many() (digits/model/images/classification/views.py@288)

  • image_classification_model_classify_one() (digits/model/images/classification/views.py@231)

You can also view the outputs (ROC curves) of classification by calling the image_classification_model_large_graph() method from the file (digits/model/images/classification/views.py@218). The final outputs would look something like the images below.

The TOP-N classification of images is also supported by DIGITS and can be accessed by calling the image_classification_model_top_n() method from (digits/model/images/classification/views.py@364)

The visualization of the learning rate graph can be acquired by calling the models_visualize_lr() method from (digits/model/views.py@99)

You can obtain a visualization of the neural network that you use for creating your model by using the models_visualize_network() method from (digits/model/views.py@86)

Caffe Interface¶

This section explains how DIGITS interacts with Caffe under-the-hood to perform Classification tasks and output the visualization plos (ROC plots and Loss curves) for the same. We would be tackling this part in three sections, views, digits-backend and caffe-backend.

Views¶

  • The views are where the first function calls are made for every user action. Mainly, the Caffe related tasks are handled from the file ‘show.html’ (digits/templates/models/images/classification/show.html(@149-184) which handles the respective JS function calls for classify_one() and classify_many() methods which have been defined in the same file itself at line (digits/templates/models/images/classification/show.html(@195) and (digits/templates/models/images/classification/show.html(@221) respectively.
  • These JS functions call the image_classification_model_classify_many() (digits/model/images/classification/views.py@292) or image_classification_model_classify_one() (digits/model/images/classification/views.py@236) in the backend.

DIGITS Backend¶

  • All the parameters required for training the network are converted to the format suitable for viewing using C3.js libraries in the frontend and to a format suitable for Caffe in the backend in this section.
  • The ‘train.py’ file (digits/model/tasks/train.py) is responsible for carrying out these tasks. The lr_graph_data() (digits/model/tasks/train.py@420) returns data to views formatted in a format suitable for C3.js linrary. Similarly methods loss_graph_data() (digits/model/tasks/train.py@445) and accuracy_graph_data() (digits/model/tasks/train.py@488) do the respective tasks. Also, there’s a method combined_graph_data() (digits/model/tasks/train.py@531) which handles all the graphs’ data points in one big graph.

Caffe Backend¶

  • This section describes how the under-the-hood tasks are executed between Caffe and DIGITS. The PyCaffe interface is used to process Caffe realated tasks. The ‘caffe_train.py’ file (digits/model/tasks/caffe_train.py) is responsible for carrying out these tasks.
  • The save_prototxt_file() (digits/model/tasks/caffe_train.py@115) function in this file is where the input prototxt file is converted to a caffe_pb2.SolverParameter() [i.e. with all the training parameters stored in python variables] and stored in the self.solver variable for use later by all them methods defined in this Training class.
  • The process_output() (digits/model/tasks/caffe_train.py@399) method converts the output of caffe line-by-line into a DIGITS displayable format. This task is accomplished using regular-expressions on the lines of output.
  • The classify_one() (digits/model/tasks/caffe_train.py@621) method returns a two-pair list of label and confidence for a given input image and the get_layer_visualization() (digits/model/tasks/caffe_train.py@726) method is called from the previous method to obtain a vis_square of the data of classification.
  • Similarly, the method classify_many() (digits/model/tasks/caffe_train.py@829) does the above tasks in a loop for multiple images.
